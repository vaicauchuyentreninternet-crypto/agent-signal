Agent Signal

Methodology

Everything here is reproducible from public GitHub data. No secret signals, no paid rankings.

Sources

GitHub Search API (search/repositories, sorted by stars) plus the REST /repos endpoint for a small hand-maintained Hermes ecosystem list. Queries are stored in scripts/fetch_trends.py; a token is optional (unauthenticated rate limits apply, ~10 searches/min).

Score formula (0–100)

Momentum 0–40: stars gained over the last 7 days, from daily snapshots in data/history.json. Until history exists, momentum is unknown and the total is marked provisional.
Activity 0–25: push recency (12 pts if pushed within 7 days), fork count, issue load.
Fit 0–25: curated 0–10 × 2.5. Curated entries live in config/fit_scores.yaml with a one-line reason tied to Hermes or our current projects. Uncurated repos get a neutral 5.0 and are labelled “not curated yet”.
Docs 0–10: known license + substantive description.

Known limits

• Stars measure attention, not quality — a marketing spike can outrank a solid tool.
• Search queries catch repos by topic keywords; relevant projects without topics can be missed.
• Delta requires history: the first run after setup always shows NEW.
• Fit scores are our own judgement for our stack, not community consensus.
• Scores are auto-generated and must not be read as endorsements.
